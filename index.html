Show Me What Game You Can Build v2

This project hands one prompt to different language models and gets out of the way. Each model is given its own folder and told to build an original browser-based game that a human would find incredibly fun to play — with a storyline, evolving gameplay, and no more than 10 minutes of playtime. It can work for as long as it wants. The only rule is that it must not look at the other models' folders.

The prompt

Every model received exactly this, with only the bracketed placeholders filled in:

You are the [MODEL_NAME] model on [HIGHEST_THINKING_MODE] thinking. I've heard you're a remarkable and highly creative model. This repo is a github pages site. Your workspace is the [FOLDER_NAME] folder.

I want you to build an original browser-based game that you think will be INCREDIBLY FUN for a human to play. Something that'll blow their minds and have them walk away from their computer thinking "WOW! Now that was something!".

Game requirements:
- The game must have a storyline. The storyline must incite some emotion whether it's delight, joy, laughter, fear, melancholy, or something else.
- The gameplay dynamics must either evolve or vary over the course of the game. It shouldn't be the same mechanic or action that's repeated across the entire game.
- You do not need to optimise the game for mobile. Design the game for a macbook air screen, keyboard, and (optionally) mouse.
- You are free to choose the art style (try to impress the player with something other than SVG graphics).
- You are free to choose the genre of the game.
- It should be deployable to a github pages site.
- The total playtime of the game should be no longer than 10 minutes. This excludes the time required for the player to learn the controls.
- The game should be challenging in some way. It shouldn't be a breeze to play. But it shouldn't be so difficult so as to enrage the player.

Build a game that TRULY demonstrates your capabilities and impresses the person playing it. Push yourself to the ABSOLUTE MAXIMUM! Blow my mind!

Rules:
- Once you're done building the game, you must add a link to it, and a brief description of the game to the index page (so I can easily access it when I visit the github pages site).
- Make sure the description is written as if a salesman or marketer had written it. Sell your game with the description! You should write no more than 25 words.
- DO NOT peek at the index page until after you're done building the game. I don't want you cheating and getting ideas from the other models that also did this.
- DO NOT change the design of the index page.
- DO NOT peek at any other models workspace folder. That would be CHEATING.
- You DO NOT have to access any files outside of your workspace folder. Any attempt to do so will be rejected.

Also, no one is going to verify your work for you (e.g., that the game works and is playable). No one is going to tell you what to improve and refine. You must do all this yourself before you say you're done with this challenge.

Now go! Go forth and design an awesome game!

Caveat: we can't guarantee the models didn't cheat by looking at each other's work. This was never meant to be a pure, zero-cross-contamination experiment — it's just a fun side project.
